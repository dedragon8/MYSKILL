# 交付、更新与飞书接口

## 默认写稿交付

用户只要脚本时，每条给“编号／角度”和按自然语义断行的口播正文，少加说明。分析、依据与未知参数放正文外，避免主播误念。用户要策略或批量投放表时再附目标产品、拉新假设、主卖点、预计时长、测试变量等字段。

按最新创作规范：默认完整稿 20–30 秒，30 秒约 120–150 个汉字，以自然语速和停顿校正。用户有明确字数上限时严格计数；未给字数口径时可按可见正文字符保守计算，数字与英文不用于规避限制。初稿和飞书口播正文保留正常标点，自然断行，不提前套用字幕去标点规则。用户只要方向、开头或局部修改时只交付该范围；保留认可的钩子与语气。

缺少客观信息时优先改写为只使用已确认事实的可用稿。必要时另列待确认项；含占位符的稿明确标成待完善，不能标为可直接投放。品牌层通用草稿也不能凭空加入“纯棉”“有认证”等尚未确认的全系列共性。

建议稳定记录字段：脚本 ID、版本、产品范围、需求入口、口播正文、进房理由、事实依据、待确认项、用户反馈与状态。编号和版本用于后续修改、同步和对照，不强制为了短答展示整张表。涉及字数和预计时长时区分估算与真实试读；不按固定语速保证秒数。

## 逐步吸收信息

- 新产品资料：更新 products.md，对应具体系列与来源日期。
- 新参考文案：追加案例，保留原文与编号，注明用户认可点；将语言观察与事实主张分开。
- 语言反馈：用户说“以后不要某个称呼”等通用要求时更新 brand-language.md；一次性修稿保留适用范围。
- 拉新测试：记录脚本版本、主变量、用户提供的数据口径与条件，更新 acquisition.md 中相应假设，不删除不利结果。
- 品牌定位发生变化：以最新明确指示为准，更新主文件与对应参考，避免多处信息冲突。

## 飞书同步：接入状态与执行方式

使用前检查当前环境的飞书 CLI 安装及登录状态，并核验目标文档的读写权限。具体文档链接、应用配置、身份与同步回执只保存在本地，不随公开技能分发。

执行入口为 `lark-cli`。操作前读取已安装的 `lark-shared`、`lark-doc`、`lark-drive` 对应说明，并显式指定 `--as user`。凭证由 CLI 管理，不写入技能或脚本库。根据实际所缺权限定向处理。

### 每批目标确认与命名

用户于 2026-11-02 明确要求：每批写入前，询问“这批脚本是新建飞书文档，还是写入当前的《文档名》？”并附当前文档链接。必须等选择后再云端写入；等回复时可完成本地草稿，不以默认值或等待超时替用户选择。本次指令已明确选择新建／使用某文档，则视为已回答这一问题，不再重复询问。文档选择只覆盖当前批次，不自动永久延续。

- 新建：先确定文档名和脚本日期。已有明确日期与命名惯例时可用“M月D日千川脚本”，不必重复询问已知信息；日期不明且影响标题时定向询问。一次创建，取得 ID 后继续在该文档修复与核对。
- 使用当前：展示并核对当前文档身份，写入用户选择的那一份；有多个候选而无法定位时请用户给链接。
- 通用脚本标题：`YYYYMMDD_多品混剪_口播_主题`。日期依据脚本批次，例如 11 月 7 日即 `20261107`，不是写入当天。主题用“周末宅家”等简短描述，同批同主题多条可加 `01`、`02`，避免冲突；更新同一条时保留稳定 ID 与标题，不另造新稿。
- 每条脚本标题必须是 H3：`<h3>20261107_多品混剪_口播_周末宅家</h3>`。用户此要求优先于通用“不跳标题层级”的建议，不添加虚设上级标题。文档自身标题仍为 `<title>`。
- 批次变更时只调整日期、主题及用户明确更改的制作类型，沿用命名格式。后续用户明确指定其他格式时更新约定。

同步内容以用户当前要求的版本为准，正文与内部策略注释分开；默认不把投放假设、未核实卖点混进可口播正文。文档按“文档名 → 各脚本 H3 标题 → 逐行口播正文”组织。

自动同步前落实稳定脚本 ID、版本与目标文档位置的对应关系，避免重跑重复追加。已有内容先读再定点更新，保留用户手动编辑，遇到冲突呈现具体差异再解决。写入结果未知时先读回核对，不能盲目重试创建。

同步后必须读取核对文档 ID、标题、H3、最新正文及内容范围，再提供可访问链接并执行下述私聊通知。没有写入成功的证据就不说“已同步”；失败时保留本地成稿并说明真实状态。

### 飞书完成通知

飞书通知仅在当前用户明确授权后发送给已核验的本人；不群发，不使用加急、短信或电话。

通知前核验当前账号的本人 open_id 和应用身份；这些值仅保存在本地。切换应用或账号后重新核验，不沿用其他应用的标识。

发送前读取官方 IM 参考：`lark-cli skills read lark-im/references/lark-im-messages-send.md`，并按需查 `lark-shared`。命令采用 `lark-cli im +messages-send --as bot --user-id <已核验本人open_id> --text @./通知文件 --idempotency-key <本批唯一键>`；根据文档 ID、批次和写入版本生成不超过 50 字符的稳定幂等键。消息正文只包含完成事项、文档名、本批条数、必要的脚本标题与文档链接。

示例通知：“已完成《11月7日千川脚本》的同步，共1条。脚本标题已使用H3。文档：<实际链接>”。确认发送成功后记录 message_id、chat_id 和本批版本；API 接受发送不等于用户已读，不声称已读。

成功后在本地记录通知回执；相同批次与版本不重复通知。

消息权限与文档权限分开。bot 缺少 `im:message:send_as_bot` 时按 CLI 返回的开发者后台链接处理，不对 bot 反复执行用户 auth login；需要用户开通应用权限或建立机器人私聊时，保留已完成文档，明确通知尚未发送，提供准确的所需操作。通知结果不明时优先核对已有回执或幂等键，不盲目发送多份；不能因通知失败重新创建文档。

未来用户明确要求定时写作、自动更新时再使用平台自动化工具配置时间和触发条件；只有本 Skill 文件不能自动启动写稿或同步。
