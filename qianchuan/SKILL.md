# 千川信息流广告 AI 剪辑师

为用户的千川信息流广告建立可追溯的剪辑判断，并用本地 ChatCut Desktop 完成可编辑的视频工程。只有用户要求实际剪辑或导出时才制作成片；学习参考视频并更新本 Skill 时，可以登记原片、读取转写和抽帧分析，保留原片不变。

## 工作入口

- 使用 `chatcut_desktop` MCP 操作本地 ChatCut。先发现目标项目，并在每个项目调用中传入该项目的 `projectId`。不要把本地工程当作托管版 ChatCut 工程。
- 按当前任务读取相关的 ChatCut 工作流 Skill：口播主导剪辑用 `talking-head-guide`，转写和字幕用 `transcription`，逐帧检查用 `visual-analysis`，导出用 Desktop 对应工具说明。仅加载确实需要的部分。
- 用户要求克隆音色生成口播时，先读[本地音色克隆配音](references/local-voice-cloning.md)，沿用其中已验证的本机 Qwen3-TTS + MLX 路线；具体参考录音以本次用户指定和授权为准。生成后再按真实音频做字幕与剪辑。
- 剪辑前先按下文“剪辑前读取规则库”查阅已确认规则、品牌方向与相关案例；`references/learned-rules.md`（若存在）继续保留并读取。规则不得覆盖用户本次明确要求，也不得当作对所有商品或账号都适用的事实。

## 剪辑前读取规则库

收到新的剪辑任务时，先读 `references/case-index.md`、`references/editing-rules.md`、`references/subtitle-style.md` 和 [品牌审美与导演决策](references/visual-direction.md)，再按商品、脚本结构、卖点和目标选择相关 `case-00N.md`。只采用已确认且适用于该场景的规则，先形成镜头与字幕方案，再在 ChatCut 中编辑。当前 9:16 画幅和用户已保存的 MiSans 字幕参数仍是默认设置；案例中观察到的样式不自动覆盖它们。若规则文件尚未建立或某项结论标为待验证，明确这一点并依据本次素材作判断。

## 品牌导演判断

为 NIGHTOLOGY 晚安学剪辑时，按 `references/visual-direction.md` 核对品牌定位、候选镜头的语义与审美、开头钩子、景别与节奏变化。执行 ChatCut 操作前，先完成该文件中的导演决策，明确传播目标、关键视觉信息、材质与空间画面的分配、应降低优先级的素材及相关成功案例。不要仅凭文件名或素材顺序拼接；画面信息不足时先检查关键帧或实际视频。导出前按该文件检查渲染画面与字幕，无法确认的审美判断标记为需人工复核。其他品牌任务以本次品牌要求为准，不机械套用晚安学的受众和审美定位。

多品、多款口播广告优先读[006：用户修改后的多品丰富度](references/case-006.md)，按用户2026-11-10认可的款式、景别与生活动作覆盖执行；详细规则见[已确认偏好](references/learned-rules.md)和R10。此参照不扩大单品范围，也不固定开头形式或镜头时长。

## 固定画幅与字幕样式

本 Skill 制作的所有视频使用 **9:16 竖屏画幅**，以 1080×1920 为基准。导入其他比例的素材时，在竖屏画布内调整取景与裁切，保持主体完整，不拉伸画面。新工程和导出都检查为 9:16。

默认以用户在 ChatCut 工程“千川自动字幕测试 003 - 匹马棉”中保存的字幕设置为基础；按用户2026-11-03要求，将字重升级为 **MiSans Bold 加粗（700）**。以 1080×1920 画布为基准：

- 字幕字体 **MiSans Bold 加粗**，字体家族使用 `MiSans`，字重 `700`，白色 `#FFFFFF`；单行、水平居中，字幕框位于画面下方。字幕框参数：`left=161.9921875`、`top=1213.0044473276832`、`width=756`、`height=289.77777777777777`（画布像素），垂直对齐 `flex-end`。在其他 9:16 分辨率上按画布比例缩放这组位置和尺寸。
- 字幕项的基础样式：`align=center`、`displayMode=single`、`maxLines=1`、`fontFamily=MiSans`、`fontStyle={variant:normal,weight:700}`、`color=#FFFFFF`、`punctuationMode=default`。可见中文字幕轨道覆盖样式：`fontSize=0.054`、`fontStyle={variant:normal,weight:700}`、`lineHeight=1.1`、`textShadow="0 1.5px 4.7px rgba(0, 0, 0, 0.51)"`、`verticalAlign=flex-end`、`preset=custom`。共享外观在字幕轨道统一设置；若旧卡片自身仍覆盖为细体，移除相应字重覆盖以继承轨道加粗，保留其他有意的局部样式。应用后检查实际渲染为加粗及文字没有溢出；优先按自然语义缩短断句。
- 中文字幕按自然语义停顿分为短句，显示文字不加逗号和句号；保留 `100%` 等属于内容的符号。不要用 `punctuationMode=none` 一概去标点，因为它也会去掉百分号；逐条校对显示文字。

这些是后续剪辑的默认设置。用户对某支视频明确指定不同字幕或画幅时，以该次要求为准；用户确认新的通用设置后再更新这里。

## 成功案例学习

用户提供案例后，先确认可访问的视频、脚本、素材和用户认定的成功点。检查实际成片，按时间线记录可观察证据：开头钩子、卖点和转化结构、镜头时长与切点、画面如何支撑口播、字幕的字体与层级、强调方式、位置和节奏。区分观察到的做法、推测的效果和用户明确认可的规则；不要从单个案例推断投放表现或通用最佳实践。

新增成功案例时，先形成带时间码和证据边界的 `references/case-00N.md`，再增量更新 `references/case-index.md`。比较已有案例后，只把经用户确认、稳定且可执行的策略写入 `references/editing-rules.md` 或 `references/subtitle-style.md`；原有 `references/learned-rules.md` 若存在则保留。每条规则注明适用场景、操作方式、案例证据、例外或待验证点。用户明确要求把已认可案例学习写入本 Skill 时，完成证据分析、备份后直接增量保存，并在交付时说明新增规则与边界；超出其认可范围的推测先标待验证。不机械平均不同案例，也不悄悄覆盖旧规则。用户明确纠正的规则应更新或标记为废弃。

生活化床品质感混剪可优先参照[004：不叠被子](references/case-004.md)与[005：不一样的纯色](references/case-005.md)：用生活动作与自然床景开题，再通过景别、光线下的织物形态和手部动作解释质感；句子可跨镜头，切点照顾完整动作；品牌可叠在真实使用画面上收尾。具体操作与例外见 `references/editing-rules.md` 的R7–R9。案例混剪不扩大用户本次授权的产品范围。

## 剪辑与交付

### 素材库检索与反馈回写

剪辑前加载 `material-library` Skill，并查询 `~/.codex/qianchuan-data/materials.db`。**以用户本次指定的素材范围为准**：可指定完整分类、颜色、某个产品型号（如 80支磨毛）、型号族（如 120支）或整个系列（如全部条纹）。只用 SQL 查询该范围内有限的候选记录，不读取全库每条素材或全部 Contact Sheet；名称不明时先查 `list-scopes` 分类摘要，仍不清楚则问用户。范围检索只表示可从这些产品中选镜头，不把不同型号或颜色当作同一单品。按口播卖点、构图、动作和审美评分选候选，向用户说明路径、源素材粗候选时间码与理由。混合素材已标注，默认不作为单品展示；用户明确允许混合画面时用 `--allow-mixed` 检索，并说明画面中的各产品。若已分析素材不足，明确告知。入选后用 ChatCut `inspect_asset` 在候选范围内按 0.1–0.2 秒抽帧，识别动作起止、高潮、最佳构图和切点；大幅或重复运动继续缩小到相邻源帧，并将每次起止点记录到 `motion_events`，再确定精确源入出点和恒定变速；`preview_timeline` 复核实际成片。不要把初学阶段的稀疏抽帧时间码冒充精确切点。

“多品纯色合集1.mov”和“多品纯色合集2.mp4”仅用于全系列混合展示（用户2026-11-10确认）。本次范围明确为不限型号的全系列混合画面时，额外调用 material-library/scripts/material_db.py search-collections --all-series；指定单个型号、颜色、单品或局部系列时不用，即使允许该局部范围内混剪也不扩大到这两条合集。

开箱视频、认证图片/PDF、音效等辅助素材按 `material-library` 的待确认流程分类。仅将已确认且与当前产品、口播语义匹配的内容放到相应话语处；认证资料须核实适用产品和可支撑的表述，不由图片自行推断宣称。用户已确认 `认证文件` 文件夹中的三张图适用于所有产品；分别区分报告首页和 OEKO-TEX 宣传图，保留其可见证据边界，不把宣传图称为证书。口播提到相应认证时可选用，但展示优先采用与原画面融合的叠加或柔和过渡，避免突兀的整屏硬切；检查字体可读性、产品主体和字幕遮挡，以实际成片和用户后续修改意见逐步调整。对其他内容或用途不明的素材向用户提问，保持数据库待确认状态。

用户已说明 `包装、开箱` 的视频按**动作**而非具体产品归档。口播或画面要求出现开箱、交付、仪式感时，额外查询 `material_db.py search-generic --role unboxing`，按动作描述选择；未提到这类画面时不读通用库。分清盒子入画、摆放、掀盖、取出、盖回、移走，不把相邻动作互相冒充。大幅或重复动作逐帧核准每次起止点再剪。

用户提出镜头替换、保留、切点、速度或审美修改时，按 `material-library/scripts/material_db.py feedback` 写入素材或片段级反馈，标明当前工程与适用范围；下一次检索参考反馈排序。只有用户确认且可迁移的偏好才按下方“反馈迭代”写入 `references/learned-rules.md`，一次性修改只留数据库。反馈不得覆盖原始视觉证据。

转写故障处理：若 ChatCut 转写报 `spawn ffprobe ENOENT` 或类似本机组件找不到的错误，先确认源文件可读、ChatCut Desktop 是否已退出。应用关闭后的后台工具环境可能缺少组件路径；可重新打开或重启 ChatCut，再对同一素材重试转写并确认词级时间码。重试成功后按实际转写处理口播与字幕；重试仍失败时查看日志并说明具体阻塞，不能直接用文案和波形猜测字幕时间后当作已核准。

运镜切点复核：入选镜头应检查相机运动、主体动作、前景遮挡的开始与结束；对每个实际入点和出点抽取相邻源帧，并用 `preview_timeline` 检查切点两侧。避免在前景遮挡未退出、动作尚未完成或同一运镜中间跳到不连续源时刻时切入；不能仅按口播句长把候选素材截成固定秒数。先完成口播删改，再重排镜头，尤其核对前 3–5 秒。

收到用户的口播音频、参考文案和指定画面/产品后，核对素材可用性、9:16 画幅、时长及交付要求；缺少关键信息时先从素材和既有项目判断，再只询问无法合理推断的部分。**实际口播音频是内容与时间的基准**：先转写和听审，标出文案与音频差异；字幕、剪辑结构以音频中实际保留的话为准，不擅自用文案替换讲话。按 Desktop `transcription` 与 `talking-head-guide` 工作流处理固定口癖和无意义气口，再以语义判断口误、重录和重复句，保留自然呼吸、语意和句间停顿；复听每处拼接。只在明显拖慢广告节奏且不会损害音色、清晰度时适度加快口播，先试听再决定速度，不机械追求快。先确定口播结构与删改，再依据语义和证据选择画面。优先让镜头展示当前口播所说的产品、动作或结果；无法直接对应时选择不误导的相关画面。保留可读的镜头节奏，并使字幕与真实语音同步。

同一条视频剪辑时检查镜头去重：默认不重复使用同一源素材的同一时间片段；即使时间片段不同，若构图、动作和画面内容几乎相同，也按重复镜头处理。优先换用指定产品范围内的新素材，或同一素材里视觉上明显不同的动作、景别。仅在可用素材严重不足，或其他候选画面与产品、口播语义明显不匹配时例外，并在交付时说明。

后续音效库先登记、试听和分类；优先用柔和的被褥摩擦声、低调白噪音或契合空间的环境声增强质感，音量不能盖过口播。避免廉价、突兀的转场音效；不为每次切镜强加音效。检查素材间明显的色温、曝光和色调跳变，仅在差异影响衔接时用 ChatCut 可用的基础调色参数微调，以真实产品颜色和相邻镜头为参照；差异不明显则保持原样，不做夸张浓郁的整体风格化调色。预览切点两侧的真实成片画面和声音。

用户再次明确音效要克制、自然、有质感（2026-11-03）。选用前读[音效与环境声](references/audio-use.md)，只查询与本次画面相关且已实际听审的音效；技术扫描完成不等于听审完成。不把每个切镜都做成声音事件。

默认按上述 MiSans 字幕样式制作字幕；用户另行指定字体或样式时按当次要求处理。检查字形、对比度、安全区域、断句和重点强调。若所需字体文件或授权使用范围不可用，说明缺口并请求可用字体，不擅自替换成看似相近的字体。剪辑中保留 ChatCut 可编辑工程；完成后检查关键段落的实际画面、声音和字幕，导出 MP4，并向用户说明工程位置、导出文件和仍需人工判断之处。不要仅以工具返回成功代替成片检查。

## 反馈迭代

收到修改意见后，先定位到具体片段并修改工程；复查修改后的画面、声音和字幕。将用户明确认可、且可迁移到后续广告的偏好更新到 `references/learned-rules.md`，注明反馈来源与适用条件。一次性的素材修正或未验证猜测不写成长期规则。
